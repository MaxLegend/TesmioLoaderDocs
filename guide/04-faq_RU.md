# FAQ — Часто задаваемые вопросы

## Общие вопросы

### Что такое Markdown Viewer?

Markdown Viewer — это лёгкий статичный просмотрщик документации, который отображает `.md` файлы из папки `guide/`. Он автоматически строит навигацию в боковом меню, поддерживает несколько языков для каждого документа и работает на GitHub Pages без этапа сборки.

### Нужен ли мне инструмент сборки (Webpack, Vite и т.д.)?

**Нет.** Просмотрщик состоит из чистых HTML, CSS и ванильного JavaScript. Просто опубликуйте файлы на GitHub и включите Pages.

### Можно ли использовать это без GitHub Pages?

Да. Просмотрщик работает на любом статическом файловом сервере: Netlify, Vercel, Cloudflare Pages, nginx, Apache или даже локальном `python -m http.server`. Интеграция с GitHub API используется только тогда, когда сайт размещён на `*.github.io`.

## Файлы и навигация

### Как просмотрщик находит `.md` файлы?

Используется трёхэтапная стратегия:

1. **GitHub Contents API** — При размещении на `*.github.io` выполняется запрос к `api.github.com/repos/.../contents/guide` для динамического получения списка файлов.
2. **`manifest.json` fallback** — Если API недоступен (например, из-за лимитов или локального запуска), читается `guide/manifest.json`.
3. **Встроенный fallback** — Если оба способа не сработали, используется встроенный список (только для разработки).

### Как группируются локализованные файлы?

Файлы с одинаковым базовым именем, но разными суффиксами `_XX` группируются вместе. Например:

- `00-getting-started.md` → язык `EN` (по умолчанию)
- `00-getting-started_RU.md` → язык `RU`

Они отображаются как один элемент в боковом меню с переключателем языка.

### Можно ли использовать другой формат кода языка?

Сейчас поддерживаются только двухбуквенные коды в верхнем регистре (например, `_RU`, `_ES`, `_DE`, `_ZH`). Если нужны трёхбуквенные коды, измените регулярное выражение в функции `parseFilename()` в `app.js`.

### Как определяется заголовок документа?

Просмотрщик пробует эти источники по порядку:

1. Поле `title` в YAML front matter (например, `title: Мой документ`)
2. Первый заголовок `# H1` в файле
3. Slug, преобразованный в заголовок (например, `getting-started` → `Getting Started`)

### Как сортируются документы?

По числовому префиксу в имени файла. `00-` идёт первым, `01-` следующим и так далее. Файлы без префикса сортируются последними (обрабатываются как `9999`).

## Возможности

### Поддерживается ли подсветка синтаксиса кода?

Да, через `highlight.js` (загружается из CDN). Поддерживаемые языки включают JavaScript, Python, Bash, JSON, HTML, CSS, SQL, Go, Rust и более 190 других. Тема автоматически переключается между светлым и тёмным вариантами.

### Поддерживается ли GFM (GitHub Flavored Markdown)?

Да. Таблицы, списки задач (`- [x]`), зачёркивание (`~~текст~~`) и авто-ссылки поддерживаются через `marked.js` с `gfm: true`.

### Поддерживаются ли диаграммы Mermaid?

Нет, из коробки. Чтобы добавить поддержку Mermaid, подключите библиотеку Mermaid и добавьте кастомный рендерер в `app.js`, который преобразует блоки кода ```mermaid.

### Можно ли добавить свои типы уведомлений?

Да. Отредактируйте функцию `processCallouts()` в `app.js`, чтобы добавить новые типы. Например, для типа `success`:

```javascript
const typeMap = {
    // ...существующие типы...
    'success': 'callout callout-success',
};
```

Затем добавьте соответствующий CSS-класс в `styles.css`.

## Безопасность

### Безопасен ли отрендеренный Markdown?

Да. Весь HTML очищается через DOMPurify, который удаляет опасные теги и атрибуты (например, `<script>`, `onerror=` и т.д.). Пропускается только безопасный HTML.

### Могут ли просмотрщики выполнить JavaScript из `.md` файлов?

Нет. Любые теги `<script>` или обработчики событий в Markdown удаляются DOMPurify перед вставкой в DOM.

## Производительность

### Насколько быстрая начальная загрузка?

HTML-оболочка ~5КБ, CSS ~15КБ, `app.js` ~20КБ (без сжатия). CDN-библиотеки (`marked.js`, `highlight.js`, `DOMPurify`) в сумме ~80КБ в сжатом виде. Первая отрисовка контента обычно происходит менее чем за 500мс при быстром соединении.

### Как кэшируются документы?

Просмотрщик кэширует заголовки документов в памяти после первой загрузки. Полное содержимое загружается заново каждый раз (заголовки кэширования браузера не устанавливаются). Если нужен агрессивный кэш, настройте заголовки `Cache-Control` на вашем хостинге.

### Что насчёт лимитов GitHub API?

Анонимные запросы ограничены 60 в час на IP. Каждая загрузка страницы делает один API-запрос для получения содержимого папки `guide/`. При превышении лимита просмотрщик автоматически переключается на `manifest.json`.

::: tip
Для сайтов с высоким трафиком рассмотрите использование [GitHub Personal Access Token](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/creating-a-personal-access-token) (увеличивает лимит до 5000/час). Однако встраивание токенов в клиентский код небезопасно — для продакшена используйте serverless-функцию для проксирования API.
:::

## Решение проблем

### Боковое меню показывает «Документация не найдена»

1. Убедитесь, что папка `guide/` существует в корне сайта.
2. Убедитесь, что она содержит хотя бы один `.md` файл.
3. Если вы не на GitHub Pages, убедитесь, что `guide/manifest.json` существует и содержит список файлов.
4. Проверьте консоль браузера на наличие ошибок.

### Документ загружается с 404

Имя файла в `manifest.json` (или возвращённое GitHub API) не соответствует реальному файлу. Проверьте опечатки, проблемы с регистром (Linux чувствителен к регистру!) или спецсимволы.

### Код не подсвечивается

1. Откройте консоль браузера — если `highlight.js` не загрузился (сетевая проблема), вы увидите ошибку.
2. Убедитесь, что язык поддерживается `highlight.js`. Полный список доступен [здесь](https://highlightjs.readthedocs.io/en/latest/supported-languages.html).
3. Некоторые языки требуют явного указания: ` ```javascript` вместо просто ` ``` `.

### Тема не сохраняется

1. Убедитесь, что `localStorage` включён в вашем браузере.
2. Некоторые браузеры блокируют `localStorage` в режиме инкогнито.
3. Проверьте, не блокирует ли какое-либо расширение браузера доступ к хранилищу.
